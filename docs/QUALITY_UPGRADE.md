# 穩定性、讀取速度與綠寶石介面改善（2026-10-17）

## 已保留的玩法

開場選擇後就取得御三家；既有的「下一步」任務提示與寶可夢中心上方的鯉魚王練等方式均保留。沒有另外加一套新手任務或調整遇敵率、敵人等級。

## 存檔與同步

- `js/save.js` 集中存檔驗證、版本遷移、即時存檔與匯出匯入；`js/save_store.js` 負責驗證與備份後寫入。
- 雲端資料先驗證，再備份本機，寫入失敗不回報下載成功。
- `js/sync_journal.js` 將待同步資料保存在 localStorage，依服務、Supabase 專案與使用者隔離。失敗後退避重試，恢復網路、返回頁面或下次啟動會補傳。
- Supabase 使用現有 `saves.data` 的 `syncRevision` UUID，PATCH 加上版本條件與 `return=representation`。初次新增不再 upsert；同時新增或版本條件不符會保留衝突，不會盲目覆寫。既有資料表與 RLS 可沿用，不需新增資料表。
- GitHub Gist 上傳前檢查遠端版本，上傳後再次確認，並保留最後上傳的本機分支與 Gist 自身的版本歷史。Gist REST API 沒有本專案可用的原子版本條件更新；需要嚴格防止雙裝置同時覆寫時應使用 Supabase。不能把 Gist 的檢查宣稱為原子 CAS。
- 「帳號」選單可以比較、選擇本機或雲端進度，也可匯出雙方及保留的復原副本。野外右上角區分本機已存、同步中、失敗等待與雲端已同步。
- `js/lifecycle.js` 在切背景、離開頁面與定時檢查時，只保存安全的野外狀態。戰鬥、對戰塔、移動與尚未結束的互動不寫入。離開頁面的網路請求只是盡力補傳；可靠性來自持久保存的待傳資料。

## 更新與離線

- 每次 Vite 建置自動產生版本與必要檔案清單，包含 HTML、入口模組、資料模組、CSS 與主要字型。
- 必要檔案全部下載成功才安裝新 Service Worker。新版等待玩家選擇「儲存並更新」，不在戰鬥中強制重新載入。
- HTML 與無雜湊檔案採網路優先；帶雜湊的資源採快取優先。保留舊雜湊資源，避免仍開著的舊分頁缺檔。
- 快取依網站路徑隔離，不清除其他應用程式的快取，查詢參數不再被忽略。
- 離線可重開已快取的遊戲；未下載過的外部寶可夢圖片、素材與 Z 動畫仍需要網路。

## 結構與測試

- 將存檔模組從遊戲迴圈拆出；加入共用資料的 JSDoc 型別契約。
- `js/battle_hooks.js` 提供依優先順序執行的明確擴充點，將極巨化、形態與團體戰的六個巢狀覆寫移入事件處理。其餘機制保留原實作，逐步遷移。
- 野外遇敵統一使用 `U.rand()`，固定亂數可重現這項判定。
- Playwright 收集到的 `pageerror` 現在會使測試失敗。
- 新增雙裝置同時寫入、重開後補傳、損毀資料、儲存額滿、安全背景存檔、Gist 衝突副本與事件順序測試。
- 增加正式打包版測試：存讀檔、動畫延遲載入、離線重開、新版等待啟用、舊資源保留與 URL 查詢參數隔離。CI 在 build 後執行。

## 手機與美術

- 手機戰鬥選單在遊戲縮放區外呈現，按鈕至少 44×48 CSS pixels。先點招式預覽，再確認使出；PP 耗盡的招式仍可查看原因，但不能確認。
- 測試尺寸為 360×800、390×844、844×390，涵蓋返回、PP 與太晶化切換。
- 檢查標題、野外、主選單、隊伍、能力、背包、圖鑑、商店、箱子、設定、任務、戰鬥與進化畫面，以及手機主要畫面。
- 標題改用既有 pokeemerald 圖塊重組的像素標誌與烈空坐背景；建置程式為 `tools/build_title.py`，由 `tools/build_ui.py` 納入。沒有原作素材時使用綠色系的 SVG 備援。
- 新增手機面板、狀態、任務提示與特殊能力列統一硬邊框、有限配色，移除這些介面的圓角卡片和彩色漸層。既有綠寶石背景調色盤保留。

## 讀取與遊玩紀錄

- Z 動畫改為動態模組，只在首次使用時下載；失敗時退回原有動畫。
- 圖鑑說明只在開始新遊戲或開啟圖鑑資料時下載。野外圖塊、建築、人物在進入遊戲時才準備，不阻塞開場。
- 大型生成資料拆成獨立雜湊模組，更新介面程式時可以重用資料快取。
- 遊玩紀錄增加本機任務階段耗時、戰鬥與戰敗、重複戰敗位置、長時間停留觀察。這是回饋工具，不會把停留直接認定為迷路，也不自動調整玩法或上傳資料。
- 尚未進行真人玩家研究，也未用玩家實際的雲端帳號測試；雲端交錯情境由隔離的模擬 API 驗證。

## 重現方式

```sh
npm test
npm run build
npm run test:production
npm run test:mobile
npm run dev -- --port 4321
node tools/ui_review.mjs http://localhost:4321 test-results/ui-review
npm run preview
node tools/perf_check.mjs http://localhost:8080/ test-results/performance.json
```

效能工具以三個全新瀏覽器內容、390×844 觸控、CPU 4 倍降速、40ms 網路延遲及 10Mbps 下載量測開場可操作的中位數。它是同一台電腦上的模擬比較，不代表所有手機的載入時間。

API 語意參考：[PostgREST 條件更新](https://docs.postgrest.org/en/stable/references/api/tables_views.html)、[GitHub Gist 版本與更新](https://docs.github.com/en/rest/gists/gists)。


## 本機驗證結果

- 引擎 598/598、冒煙 22/22；包含手機、同步與擴充點的 12 個 Playwright 測試全部通過。
- 正式版 4 個測試通過（包含沒有原作素材的備援）。
- 18 個桌面／手機巡覽畫面沒有未捕捉的瀏覽器例外。
- 相同模擬條件下，開場可操作中位數由 1,247ms 降至 913ms，約快 27%；可操作時已完成的資源請求由 37 降至 9。初次 JavaScript 傳輸量約 458KB gzip → 456KB gzip，主要收益是避免開場等待野外素材與圖鑑說明，以及之後可分別快取資料與程式。三次數值分別為修改前 1255/1242/1247ms、修改後 931/913/911ms。
